# 机群

几台机器组成一个机群。中心（dev2）登记每台机器、知道怎么连到它的 Paseo，并把每个派出去的活记成一个 Markdown 文件。每台机器有一个默认 Agent，派过去的活由它来干。

## 看

- `fleet nodes`：有哪些机器、在不在线、默认 Agent、标签、在跑几个
- `fleet ls`（可加 `--to dev3`、`--status running`）、`fleet show <编号>`：派活记录、来回追问和结果
- 页面：中心的 6780 端口（地址见 `~/.config/fleet/node.json` 的 `hub`）

## 派活

```
fleet run <机器> "任务"            # 派出去就继续干别的，之后 fleet show
fleet run <机器> - < task.md       # 任务长就从文件读
fleet run <机器> "任务" --wait     # 要等结果才能往下走时
fleet reply <编号> "追问" [--wait]  # 让同一个 Agent 接着干（它还记得上下文）
fleet stop <编号>                  # 叫停还在干的活
```

对方看不到你的对话和文件，任务要写到它单独也能干完：目标、背景、输入在哪（对方机器上的路径或链接）、交付什么、怎么算做完。对方默认在它自己的 `~/fleet/work` 里干活，要在某个仓库或目录里干，就在任务里写明路径（或加 `--cwd`）。

挑机器看它有什么：要公司内网资源选内网机器，要公网选 150，要某个登录态或仓库就看标签和用户说过的话；对方离线就换一台或告诉用户。不派给自己。

派活一律走 `fleet`，不要直接用 Paseo 工具在别的机器上建 Agent，那样不进记录。

## 知识中心

机器、账号、密码、密钥、API Key、模型这类日常操作要用的通用知识，统一放在中心的知识中心（一组 Markdown 文件，全部明文）：

```
fleet kb                     # 原则和目录，先看这个
fleet kb machines/dev4.md    # 读一个文件
fleet kb --ls                # 全部文件
fleet kb accounts.md --put < 新内容.md   # 整篇替换（先读出来再改），新文件记得加进 README.md 的目录
```

要登录某台机器、找某个账号或 Key、不确定某台机器怎么用时，先查这里，不要自己去试。干活中发现别的 Agent 也该知道的事（新账号、密码换了、连法变了、踩到的坑），就改对应文件，过时的直接改掉。项目进展和个人偏好不放这里。

## 收到机群任务

任务开头是「[机群任务 #N] 来自 X」（追问是「[机群任务 #N 追问]」）。照常干，最后一条消息写清楚结果：做了什么、产物在哪、还有什么没做完——这段会原样记进任务记录，派活的一方只看得到它。
